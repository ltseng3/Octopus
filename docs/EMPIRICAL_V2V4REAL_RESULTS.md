# V2V4Real public prediction study: method, results, and reproduction

**Scope:** Exploratory, decision-level evaluation from *real published detection outputs* on V2V4Real. Results are **not** the dataset's official 3D detection AP/mAP, and the simulated sharing policies are **not** observations of an actual operating edge server.

## 1. What data were actually used?

The public [DMSTrack GitHub repository](https://github.com/eddyhkchiu/DMSTrack), pinned to Git commit `d3b9949499c8e68ea33060873bd1cb95b6d4d323`, contains a modified V2V4Real/KITTI validation split with the following **nine matched sequences (0000–0008)**:

| Type | Relative path in repository | Role |
|---|---|---|
| Ground-truth Car tracks | `AB3DMOT/scripts/KITTI/v2v4real_val_label/{seq}.txt` | Scoring truth |
| Separate ego detector | `AB3DMOT/data/v2v4real/detection/multi_sensor_differentiable_kalman_filter_Car_val/ego/{seq}.txt` | Agent A's candidate |
| Separate partner detector | `.../multi_sensor_differentiable_kalman_filter_Car_val/1/{seq}.txt` | Agent B's candidate |
| CoBEVT cooperative detector | `.../detection/cobevt_Car_val/{seq}.txt` | Another cooperative reference |
| Cooperative late fusion | `.../detection/late_fusion_Car_val/{seq}.txt` | Shared edge-result candidate |

Full paths are generated by `scripts/prepare_dmstrack_v2v4real.py:source_paths`. There are **1,993 synchronized frames** across these nine sequences. Ground truth provides KITTI tracking records; detection files use corresponding comma-delimited KITTI-style rows. In this converted reference system, the center's **X,Z** dimensions are treated as horizontal (the vertical axis is Y). The benchmark does not apply new ego-to-vehicle transformations to these already aligned exports. If an alternative upstream export is used, explicit coordinates and transformations must be validated before applying this task.

Each detection passes a confidence cutoff **score >= 0.30**. For GT, center `(x,z)` is columns 13 and 15 (zero based); for detections it is columns 10 and 12. For a circular ROI of radius **7.5 m** centered on `(x0,z0)`, a binary prediction is positive if **any** car center falls inside the ROI; its GT label is computed the same way from actual car tracks. This is **not** geometric collision checking or 3D box overlap.

## 2. How common events are chosen

**Primary diagnostic, balanced:** per frame, select one GT Car box using index `frame mod number_of_cars` and construct a positive ROI at that center. Construct one *negative* ROI from the first eligible offset in `[+18x,-18x,+18z,-18z,+25x,-25x,+25z,-25z,+35x/+15z]` whose center contains no GT Car within 7.5m. Each frame in this split yields exactly one positive and one negative common decision. Coordinates are selected using GT **offline to define the evaluation task**, not by the edge-coordination policy. Selection induces a case-control benchmark, not representative prevalence.

**Secondary sensitivity check, fixed grid:** 12 prespecified ROIs at `x in {-40,-20,0,20}` and `z in {-10,15,40}` (meters), radius 7.5m for every frame; **23,916** total decision events, **4,052** positive (16.94%). This task gives a different marginal-accuracy ordering and guards against presenting only the balanced results.

The two separate source vehicles predict **the same** event and are marked wrong only relative to the same GT label. Scenes and neighboring frames are not presumed independent.

## 3. Empirical endpoint measurements

### Balanced primary diagnostic (nine sequences)

| Quantity | Count | Percentage |
|---|---:|---:|
| Number of events | 3,986 | — |
| Ego agent wrong | 670 | 16.81% |
| Partner agent wrong | 481 | 12.07% |
| CoBEVT prediction wrong | 325 | 8.15% |
| Late-fusion prediction wrong | 194 | 4.87% |
| **Both separately sourced predictions wrong** | **105** | **2.63%** |
| **Both consume same wrong late-fusion result** | **194** | **4.87%** |

The difference in the last two rates is **+2.233 percentage points**, a relative factor **1.848×**. It is positive in eight of the nine sequences and zero in the ninth. A paired **scene-clustered** bootstrap draws nine sequences with replacement for 40,000 trials (`seed=20261118`). The exploratory 95% percentile interval of the absolute difference is **+0.872 to +3.599 percentage points**; for the relative ratio it is approximately **1.36× to 2.38×**. It is based on **only nine scene clusters**, not 3,986 independent events, and should not be interpreted as a population guarantee.

A simple counterfactual mixture replaces the two separate outputs with one shared late-fusion output with probability `k`. The observed-candidate-based **expected** joint error is

`J(k) = (1-k) * (105/3986) + k * (194/3986)`.

The two marginal rates analogously interpolate between their separate errors and the recorded late-fusion error. **Intermediate k values are modeled policy mixtures over observed prediction candidates, not observed deployments.** The formula concerns this source-specific diagnostic task, not inferred physical hazard probabilities.

### Fixed-grid sensitivity task

| Quantity | Count | Percentage |
|---|---:|---:|
| Events | 23,916 | — |
| Positive GT labels | 4,052 | 16.94% |
| Ego wrong | 1,020 | 4.26% |
| Partner wrong | 1,718 | 7.18% |
| Both separately wrong | 291 | 1.22% |
| Shared late fusion wrong | 1,078 | 4.51% |

This task **does not show individual accuracy improving for both agents**: late fusion 4.51% is *worse* than ego's 4.26%, though better than the partner's 7.18%. The absolute joint-risk increase remains positive, but the paper should disclose the dependence on task definition rather than claim a universal marginal-accuracy reversal.

## 5. Full public source regeneration on a networked CPU machine

Python 3.10+; the dataset and model checkpoints themselves are **not required** because the committed detection text files are the model outputs. This reproduction step **does require network connectivity** to download small public prediction files (roughly tens of MB total). The complete upstream fetch wasn't run from the restricted local artifact container; all nine summaries were independently calculated from public files accessed through GitHub, while a source-verified full example trace was run end to end (see §6).

```bash
python -m pip install -e '.[empirical_download,empirical_plot,test]'
python scripts/prepare_dmstrack_v2v4real.py \
  --output outputs/v2v4real_all \
  --check empirical/v2v4real/sequence_counts.csv
python empirical/v2v4real/plot_empirical.py
```

`--check` verifies **every field** of the regenerated nine-row `sequence_counts.csv` against the shipped audited reference. It will reject mismatched data or a changed score threshold / ROI radius. Upstream files are SHA-256 tracked in `outputs/v2v4real_all/source_manifest.json`. `--offline` works when all files are already cached. To try a different radius, use `--radius 10` and omit the `--check` (or provide an appropriate new reference).

For a complete 3,986-event two-agent **CPU-only** replay:

```bash
python -m octopus_sim compare outputs/v2v4real_all/scenario.json \
  --policies local_only,always_share,mixed_local_shared \
  --reuse-grid 0,0.25,0.5,0.75,1 \
  --no-events --output outputs/v2v4real_all_comparison
```

**Never** use `always_independent` on this trace as though `edge:ego` and `edge:agent1` represented independent edge executions: both are aliases of the **same recorded late-fusion prediction**. The valid separate-prediction endpoint for this analysis is `local_only`. `mixed_local_shared` chooses exactly between two separate local predictions and one shared late-fusion result, with `k` interpreted as the probability of reuse.

## 6. Built-in source-verified replay, zero network required

For sequence `0007`, an independent GitHub re-fetch confirmed the exact `ego`, agent `1`, cooperative late-fusion, CoBEVT, and GT source file hashes. We packed 221 frames = **442 real predicted decision outcomes**; the reconstructed compact 5-bit sequence has FNV-1a-32 checksum **`0e57779e`**. The included decoder checks that checksum and the event/error totals before producing a trace. This sample has **4/442 = 0.905%** joint error with the two separate per-vehicle outputs, and **16/442 = 3.620%** when a single wrong late-fusion output is shared.

Run the included prebuilt authentic trace:

```bash
python -m octopus_sim compare examples/v2v4real_real_seq0007/scenario.json \
  --policies local_only,always_share,mixed_local_shared \
  --reuse-grid 0,0.25,0.5,0.75,1 \
  --no-events --output outputs/v2v4real_example
```

Or reconstruct from `empirical/v2v4real/packed_outcomes.json` with `python scripts/unpack_verified_v2v4real.py --help`.

The replay uses specified **modeled** transmission delays, queue capacity, and inference costs solely to exercise the simulator. These operational quantities were not measured by V2V4Real.

## 7. Research validity: what we can and cannot conclude

**Supported:** This particular shared-result policy on authentic published V2V4Real model outcomes increases simultaneous binary decision errors, even while the chosen cooperative output improves both agents' marginal errors on a GT-balanced evaluation. Independently generated vehicle predictions have nonzero empirical joint failure. The simulator can replay identical decision events, make source identity explicit, and reproduce the joint-error endpoints.

**Not yet supported:** An isolated causal effect of result *reuse* with all perception model choices held constant. Cooperative late fusion differs from a single vehicle's no-fusion prediction and consumes distinct source evidence, so the comparison changes both *model/fusion strategy* and *distribution to agents*. We have not measured the cost of actually computing, storing, or delivering these outputs to vehicles; plots using result identities are **not energy/resource-cost curves**. Likewise, decision-event failure is not vehicle collision risk, actual deployment safety, or empirical proof an edge-aware policy is optimal. The ROI construction deliberately simplifies full 3D detection into a binary task and may be sensitive to pose error or annotation conventions. External, independently annotated raw V2V4Real frames and model-checkpoint execution have not been reprocessed here. Sampled scenes and adjacent frames are correlated.

**Next experiment needed:** Compute one *identical* edge model's output for a shared scene once and multiple separately-observed instances under a held-fixed model/compute budget, then compare (a) the same inference broadcast to two vehicles, (b) two independently generated edge inferences, and (c) targeted independent verification using the same observation/task definition. Add measured per-model CPU/GPU latency, bytes and network telemetry and run a true dependency-aware edge policy on held-out scenes. Only then claim risk-efficiency optimization with calibrated resource costs.

## 8. Statistical and provenance caveats

The per-scene bootstrap resamples nine scenes; event-level Wilson intervals would be overconfident due to scene and time dependence. The scene-level source files are public but all nine raw predictions are intentionally fetched by a reproducible script rather than mirrored into this release. Redistribution and downstream data/model licensing must follow the original repositories' terms. All numeric results reported here are approximate percentages of exact counts, not published V2V4Real leaderboard measures.
